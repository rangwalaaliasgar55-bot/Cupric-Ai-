# dashi-motion

让 AI 在 **After Effects、Rive、Cavalry** 中制作能继续编辑的动效。

这个 Skill 整理了实际制作中的执行步骤、控制方式、失败现象和处理结果，并附带 3 个已运行验证的脚本。选择哪款软件，就读取哪款软件的经验。

## 核心功能

| 软件 | 制作方式 | 交付重点 |
| --- | --- | --- |
| **After Effects** | 原生图层、效果、表达式、控制层与合成 | 可编辑 `.aep`、原生渲染预览 |
| **Rive** | 原生图形、时间轴、View Model、监听器与状态机 | 可在编辑器中调整的图形和交互 |
| **Cavalry** | 母形、复制器、数组、共享进度与原生节点 | 可编辑 `.cv`、程序化运动与原生渲染预览 |

三款软件共用参考视频拆解流程：按动作划分分镜，核对方向、节奏、间距、数量和比例，再用实际导出画面对照。

## 这份 Skill 的特点

- **原生可编辑。** 字体、图形、动作和状态都有对应的编辑入口，方便制作后继续调整。
- **按软件加载。** AE、Rive、Cavalry 分开路由，避免把一种软件的做法套到另一种软件上。
- **记录跑通的路线。** 每一步都有成功标志；失败记录说明碰到了什么、怎么处理、结果如何。
- **保留经验的边界。** 实际执行过、只查过文档和根因未确认的情况分开标记，方便判断是否适用。
- **按反馈继续修改。** 从当前已确认工程接续，优先修正运动差异，保留已经接受的部分。

例如，Cavalry 中打开工程与渲染分开调用，避免本案出现的副本缺失；AE 中先枚举效果属性，避免改错数字索引；Rive 中验证点击、数据与状态变化的完整过程。

## 使用

在支持 Skill 的智能体环境中加载本仓库的 [SKILL.md](SKILL.md)，或直接让智能体读取该文件。环境需要能够访问目标软件；画布操作可使用 Computer Use。AE、Cavalry 需要已有可用应用，Rive 需要可用的编辑器会话。

请求中说明软件、现有工程或参考素材、目标动作和完成要求。例如：

> 使用 dashi-motion，在 Cavalry 当前工程中接着做第二段。先对比参考的运动方向和节奏，保留第一段，使用复制器和共享控制。

> 使用 dashi-motion，在 Rive 中绘制 Tab Bar，使用原生图形和可视状态机，让我之后能自己调整。

> 使用 dashi-motion，在 AE 中复刻这个动画，保留可编辑文字和控制层，并导出预览。

它提供制作方法和辅助工具。结果仍需在目标软件中打开、播放或渲染检查。

## 附带脚本

| 脚本 | 用途 | 运行环境 |
| --- | --- | --- |
| [video_review.py](scripts/video_review.py) | 顺序解码、按真实时间戳抽帧、生成单片或并排联系图 | Python 3、OpenCV、Pillow、ffprobe |
| [ae_inspect.jsx](scripts/ae_inspect.jsx) | 读取合成、效果属性、表达式错误和渲染队列 | After Effects 脚本菜单 |
| [cavalry_scene_report.py](scripts/cavalry_scene_report.py) | 读取 `.cv` 的节点分类、合成参数和字体定义 | Python 3 标准库 |

输入、输出路径由当前任务指定。脚本不绑定原作者的工程路径，也不负责重建完整动画。调用方式在下方对应文档中。
