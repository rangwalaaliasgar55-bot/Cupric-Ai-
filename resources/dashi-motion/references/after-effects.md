# AE：原生图层、效果与渲染

适用：在已安装的 After Effects 中创建、修改或复刻动画。默认交付可编辑 `.aep` 和实际渲染的预览；原生素材、文字、路径与控制层保留。

## 跑通的路线：Better Gradient

**实跑记录：** macOS、After Effects 2026；由应用内 `.jsx` 建立和修改原生对象，再通过 AE Render Queue 导出。初版风格近似可播放，后续按分镜修正轮廓和运动；不把初版导出成功当作相似度验收。

| 步骤 | 具体操作 | 成功标志；未达到时停在哪一步 |
| --- | --- | --- |
| 1. 对齐参考范围 | 用 ffprobe 读素材；看联系图，写出每段动作和时间范围 | 能说清本次复刻哪段、使用什么时间对应关系；不能只有“液态、渐变”风格词 |
| 2. 定位工作项目 | 读取当前项目路径，在 AE 保存本次工程或工作副本 | 标题栏和保存路径对应本次文件，既有工作仍保留 |
| 3. 建立最小原生画面 | 写本次 `.jsx`；通过 File → Scripts → Run Script File 执行。先建立主合成和当前分镜的文字、形状、控制层 | AE 中能选中并修改这些原生对象；没有出现对象时先处理执行入口，不继续堆脚本 |
| 4. 建立形态与运动 | 分开建立灰度场、颜色映射、文字或指针运动；需要挤出时先枚举并验证渲染器 | 在 AE 中输出目标时刻 PNG，能看见所需轮廓、侧面和朝向；参考不符时改这一层 |
| 5. 校准分镜 | 在相同参考时刻调整色标、字高、旋转轴和轮廓延伸，读取本次属性的表达式错误 | 修订记录最终为 0 个表达式错误，并输出过多张关键动作帧；无错误但画面错误仍需修改 |
| 6. 完整原生渲染 | 保存工程；确认本次队列项、范围、可用输出模板和目标文件，再渲染 | 本次队列项达到 DONE，目标视频更新时间改变；排队或单帧 PNG 不能代替 |
| 7. 检查交付 | ffprobe 读取视频与音轨，完整解码，查看关键动作；交付 AEP 和独立 MP4 | 该案例得到 1920 × 1080、24 fps、20 秒、480 帧及音轨；新任务使用自己的参数 |

只需导出时从第 6 步进入。`aerender` 曾确认存在，但本次详细修订的完成证据来自应用内 Render Queue；它是另一条待当前环境验证的入口，不要把发现可执行文件写成已用它完成渲染。

## 碰壁与处理

| 碰到的现象 | 当时的问题 | 后来使用的处理与证据 |
| --- | --- | --- |
| 原生效果已能播放，但轮廓和空间感仍不够像 | 先做出了风格，具体形态和动作尚未对齐 | 分镜抽帧；分别改灰度形态、文字朝向、字高和指针旋转，再出实际帧与完整视频 |
| 默认渲染器下，目标几何属性不能直接按预想使用 | 渲染器能力和所需挤出功能不能仅从“3D 图层”推断 | 枚举 `comp.renderers`，用一个临时文字检查挤出并出图；本机在 `ADBE Calder` 下跑通，别把标识固定到其他机器 |
| 亮度映射的属性与预期不符 | 数字索引误指向直方图等属性 | 枚举属性名称、matchName、索引与值；改用确认过的输入黑白点属性。属性报告确认第二项是直方图 |
| 径向延伸仍与参考的文字轮廓不符 | 所选变形方向与参考不同，单调模糊强度不能修正 | 最终用共享文字蒙版、不同水平尺度和亮度合成连续体积场，输出轮廓帧后再做调色 |

以上是本案的碰壁记录。模板语言、其他版本渲染器和 `.jsx` 权限属于复用前的环境检查，不宣称这些问题都在本案发生过。

## 接入现有工程

通过当前应用状态和项目路径确定修改对象。历史案例使用 After Effects 2026，但不能固定应用路径或版本号。已有未保存工作时，先保存当前工作或明确本次工作副本，不能直接新建项目抹掉它。

用户允许自动化时，可用 ExtendScript `.jsx` 批量建立原生图层和效果。通过当前可用接口或 `File → Scripts → Run Script File` 执行；没有必要为一次性脚本安装常驻面板。Windows 的 `afterfx -r` 用法不能直接当作 macOS 命令。

脚本先生成可编辑结构，再在 AE 中读取实际属性、表达式错误和可见画面。脚本文件写入完成不等于已在 AE 执行。需要脚本文件写入权限时，只处理实际遇到的权限项；不要把修改全部应用设置作为前置步骤。

## 分镜与控制结构

使用主合成组织分镜。可复用的视觉构件按需要预合成，例如渐变条、液态亮度场、立体指针、字母组。不要给每个图层都建预合成。

区分文字或形状、运动、颜色映射和最终纹理。将用户要反复调整的内容放在有名称的控制层：配色、厚度、展开量、运动进度等。独立动作保留必要关键帧；重复对象可共享表达式或控制器。

调整已有动画前，确认属性受关键帧还是表达式控制。清除表达式会改变行为，只在确实替换该控制方式时执行。

## Better Gradient 制作中的方法

这些是场景相关的可选方法，不是每个 AE 工程都要建立的模块。

### 液态渐变

先还原灰度形态和它的运动，再把亮度区间映射到颜色。该案例将流程拆成：

`形状或文字 → 灰度场 → 分段亮度区间 → 透明度与颜色映射 → 细颗粒`

这样可分别调整形态、色标位置和颜色。用户反馈轮廓或运动不对时，先改灰度场和动作；不要用更强的杂色掩盖差异。

### 文字和指针的立体感

先核对正面轮廓、字距、锚点、旋转轴和朝向，再加厚度。二维偏移副本与真实挤出会产生不同的侧面和遮挡，不能仅凭单帧外观认定等价。

渲染器与挤出能力的验证顺序见上表。临时探针仅用于确认当前需求的几何能力，完成后不进入主渲染队列。

### 轮廓延伸

先判断参考是径向延伸、水平拉开，还是物体挤出。案例中的“径向模糊”版本与参考横向轮廓不符，后续改为共享文字蒙版、多层水平尺度变化和连续亮度场，再进行颜色映射。

层数是当时的实现选择，不是推荐固定数量。能用更少的原生关系得到所需轮廓时，不照搬几十层副本。

## 属性与表达式的具体陷阱

优先通过已确认的 `matchName` 访问原生属性，避免中英文界面名称变化。名称和索引都应先从目标效果枚举确认。

案例中 `ADBE Easy Levels2` 的第二项是直方图，输入黑色和输入白色在第三、第四项。按猜测的序号赋值会改错对象。确认后可使用：

```javascript
levels.property('ADBE Easy Levels2-0003').setValue(blackPoint);
levels.property('ADBE Easy Levels2-0004').setValue(whitePoint);
```

同时确认属性的数值单位和范围。控制器名称用于方便用户修改，内部原生属性标识用于稳定定位。

表达式错误可通过启用表达式的属性读取 `expressionError`。没有错误还要看实际帧：错误旋转轴、色标区间或蒙版顺序可能合法但画面不对。

### 可复用脚本：AE 检查报告

使用 [ae_inspect.jsx](../scripts/ae_inspect.jsx)，不必重新编写属性枚举和队列读取。它从 `inspect-density.jsx`、`read-queue.jsx` 和 `finalize-native.jsx` 的读取部分整理而来，已在 AE 26.2.1 的 Better Gradient 工程中执行完成。

1. 打开要检查的工程。需要查效果属性时，在当前合成中选中目标图层。
2. 通过 File → Scripts → Run Script File 运行技能中的 `scripts/ae_inspect.jsx`，在保存框中选择本次 `.txt` 报告路径。
3. 读取 `PROJECT`、`COMPOSITION_COUNT`、`EXPRESSION_ERRORS_IN_PROJECT`、`SELECTED_LAYER_EFFECTS` 和 `RENDER_QUEUE`。末尾的 `REPORT_COMPLETE` 表示脚本完成；有 `REPORT_ERROR` 时按错误定位。

报告包含合成参数、当前及可用渲染器、全工程启用表达式的错误、选中图层效果的索引与 matchName、一维属性值，以及已有队列项的范围、状态、输出路径和可用模板。未选中图层时不会枚举效果；空项目的零错误也不代表目标工程通过检查。

脚本只读取项目并写报告，不改配色、属性、队列或工程文件，不触发渲染。原案例的 `export-preview.jsx` 同时修改色标再导出，不能直接当作通用导出工具，因此没有打包它。

目标时刻 PNG 的读取仍按当前合成调用：

```javascript
// main 是本次主合成；timeSeconds 和 previewFile 是本次检查时刻及 File 对象。
main.saveFrameToPng(timeSeconds, previewFile);
```

这些 API 读取和出图在制作中执行过。示例只说明调用关系，变量必须绑定到当前工程；它不包含构建完整动画的隐式操作。

## 原生导出与读取结果

1. 确认主合成、时间范围和队列项目；不要误渲染参考合成或临时探针。
2. 检查当前输出模块的可用模板。案例使用中文 H.264 模板，但其他语言、版本和机器可能没有同名模板。
3. 在 Render Queue 渲染，或使用当前安装中已确认存在的 `aerender`。若 H.264 不可直接输出，先渲染可用的原生中间格式，再转成预览 MP4。
4. 读取队列实际状态与输出路径。脚本中比较 `RQItemStatus.DONE`，不硬编码历史日志中的数值 `3019`。
5. 检查导出文件能完整解码，画幅、帧率、范围与音轨符合本次要求；观看关键动作。预览缓存或单帧 PNG 不代表整段导出完成。

只要求导出时，不改效果、表达式和合成组织。需要对比参考时再读 [参考拆解与对比](reference-video.md)。

## 案例依据与边界

- Better Gradient 初版完成了原生 AE 近似制作与可播放预览。后续修订集中处理液态亮度映射、立体字母、指针朝向、轮廓延伸与字高。
- 已有本地修订记录显示：表达式错误为 0，队列状态完成；当前交付 MP4 为 1920 × 1080、24 fps、20 秒、480 帧，含音轨。这些是该文件的证据，不能当作以后任务的默认参数或相似度证明。
- 本文以 Better Gradient 为案例，保留制作方法与验证结果；原始 AEP、参考素材和专用构建脚本未随仓库发布。复用时使用当前任务的工程。
