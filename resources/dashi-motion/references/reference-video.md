# 参考视频拆解与对比

仅在根据素材复刻或处理相似度反馈时读取。只读取已选软件的分支，不因为这份流程而加载另外两款软件。

## 从动作划分分镜

先读取尺寸、帧率、时长、视频和音频流。例如对当前素材运行：

```sh
ffprobe -v error -show_entries format=duration:stream=index,codec_type,width,height,r_frame_rate,avg_frame_rate,nb_frames -of json '/absolute/path/reference.mp4'
```

先看整片的动作顺序，再抽取分镜联系图。切分点使用完整动作的开始或结束，不用任意等长切片。对每个待做分镜记录：

| 范围 | 初始构图 | 主体轨迹 | 展开或收束 | 速度变化 | 切出方式 |
| --- | --- | --- | --- | --- | --- |
| 时间或帧区间 | 中心、占比、数量 | 方向、弯曲、循环 | 间距、尺寸、层次 | 停顿、加速、回弹 | 硬切、遮挡、连续转场 |

跟踪同一个字块或边角，避免把换字、遮挡或换层误判为位移。递归画面要分别记录外层轮廓、层间比例和中心孔洞。八圆变十四圆等数量变化不能用整体拉伸代替。

源片与工程帧率不同时，用时间对应，不直接比较相同帧编号。区分完整源片与本次选用区间，不能未经用户选择缩短参考时长后宣称逐帧复刻。

## 比例与节奏

测量相对值：字宽/圆径、纸片边长/画幅、层距/外框尺寸、停顿时长/动作时长。图形对称时先建立对称关系，确有差异再拆开调整。

两帧起止位置相同，仍可能因中途速度不同而看起来不像。至少检查转向、速度峰值、停顿和交接附近的中间帧。弹性动画重点看超出幅度、回弹次数和落定时刻。

字体纹理不重要时，仍要保留字形类别和字面比例的辨识度。字体从行书换成窄宋后，同一字号不代表相同的可见大小。

## 按分镜推进

先做当前分镜的一次完整播放，再向后接续。用户要求基于第一段继续时，在同一工程中添加分组或合成，并保留已接受的版本供比较。

被指出差异后，写清一条可观察的判断，例如“中列只向上移动，底部没有新增圆”，然后调整控制关系。不要只增加纹理、阴影或更多字块来掩盖运动问题。

## 使用原生渲染做对比

1. 保存目标工程，从目标软件导出本次范围。
2. 解码确认分辨率、帧数、视频流和所需音轨。示例：

   ```sh
   ffmpeg -v error -i '/absolute/path/render.mp4' -f null -
   ```

3. 将源片与原生渲染按时间对齐，观察原速，再按需要看慢速。
4. 抽取动作开始、中段、速度或方向变化、交接和结尾，做并排图。
5. 调整产生差异的参数，再渲染受影响范围。检查通过且没有新增问题后停止扩展验证。

Python 或其他绘图工具可用于抽帧、测量、联系图和比较，不能将这些工具生成的替代动画称为 AE 或 Cavalry 的原生渲染。

对严格的逐帧比较，顺序解码并保留时间戳。FAFA 的一次 Cavalry MP4 导出有 359 个可解码帧，但平均帧率和时长元数据存在一帧量级偏差；随机跳帧与只读元数据会误判。这个现象需要对当前文件确认，不是所有 MP4 的规则。

修改了字体后，像素差异是预期结果。保留运动的证明应检查轨迹、节奏和相应控制连接，不再声称画面逐帧完全相同。

## 可复用脚本：顺序抽帧与对比图

使用 [video_review.py](../scripts/video_review.py)。它提取自 FAFA 的 `create-previews.py` 和 `create-comparison.py`，去掉了固定路径、帧段、字体文件和方形画幅，并用各视频的真实帧时间戳取样。需要 Python 3、OpenCV、Pillow，以及 PATH 中的 `ffprobe`；复用当前环境，有缺项时再安装对应依赖（Python 包名为 `opencv-python` 和 `Pillow`）。

下列命令从技能根目录执行，路径和检查时刻换成本次素材：

```sh
python3 scripts/video_review.py '/absolute/path/reference.webm' \
  --compare '/absolute/path/native-render.mp4' \
  --times 0 1.5 3.7 \
  --out-dir '/absolute/path/review/shot-01'
```

只看一份视频时省略 `--compare`。第二份是裁剪后的片段时，可加 `--compare-offset`：第二份取样时间等于 `--times` 加该偏移。例如源片第 10 秒对应成片第 0 秒，使用 `--times 10 11 12 --compare-offset -10`。时间均相对各视频第一帧；超出帧时间范围时应修正本次取样，不用边界帧冒充。

输出为 `contact-sheet.png`、各取样帧的原尺寸 PNG 和 `report.json`。图中 Video 1 是第一个输入，Video 2 是 `--compare`；报告保留实际解码帧数、视频与音频流信息、每帧时间戳、取样帧编号和时间误差。图像按比例缩放，不把横屏素材拉成正方形。

该脚本已完成 FAFA 源片与原生 MP4 的各 359 帧顺序解码，并完成 AE 1920 × 1080 成片的 480 帧解码。它选择最接近检查时刻的帧，不做插帧、自动识别分镜或相似度打分；画面对比后仍要观看动作。每次使用新的输出目录，避免混用上次报告。

## 交付判断

- 技术检查通过只说明可播放，不说明相似度已达到要求。
- 用户接受约八成时，优先完成动作关系、主要比例与节拍；不用伪造百分比评分。
- 输出独立成片作为观看版本。对比图或对比视频用于解释差异，不能替代成片。
