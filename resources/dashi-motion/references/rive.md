# Rive：原生图形、动画与状态机

适用：Rive 编辑器中的可交互图形，如 Tab Bar、按钮、悬停和按压反馈。交付重点是能在编辑器中修改的图形、时间轴、状态、过渡和监听器。

## 跑通的路线：LUMA Tab Bar

**实跑记录：** 已登录的浏览器编辑器、原生图形与时间轴、名为 `Navigation` 的 View Model、数值属性 `selectedTab`、状态机条件和原生监听器。实际记录包含创建数字属性、把它接入转换条件、通过原生事件修改它，以及保存后点击检查；Data Binding 在这个案例中实际用过。

| 步骤 | 具体操作 | 成功标志；未达到时停在哪一步 |
| --- | --- | --- |
| 1. 绑定文件 | 获取用户指定浏览器中的真实文件和画板；已有登录会话直接使用 | 画板、图层和文件身份可见；不能只停在登录页或脚本文件 |
| 2. 完成一个 Tab 的图形 | 在 Design 中制作背板、指示器、图标路径、文字和命中区，再复制并调整其他 Tab | 每个部分能独立选中修改；对照目标检查描边、间距、曲线和基线 |
| 3. 建立原生动画 | 在 Animate 中制作各 Tab 的选中状态与指示器过渡；按需求补图标回弹、粒子消散 | 手动预览时，活动位置和配色正确，过渡中有预期的伸缩与回弹 |
| 4. 建立选择数据 | 新建或复用 View Model；本例为 `Navigation.selectedTab`，五个标签使用 0–4，并确认当前画板使用对应实例 | 在编辑器改选择值时，状态机条件可读取该属性；未读到时先查绑定实例和属性来源 |
| 5. 连接状态与点击 | 选择值分别进入对应状态；每个命中区的 Click Listener 将同一个选择属性改为该 Tab 编号 | 实际点击会先改变选择值，再改变活动状态；不能只靠手动播放时间轴 |
| 6. 加独立反馈 | 本例将标签切换、轨道、按压、悬停分层，补齐动画并避免相同属性的写入冲突 | 切换时能保留按压和轨道反馈；释放后恢复，图标、指示器和配色一致 |
| 7. 检查与保存 | 五个标签逐一点击、跨标签和连续切换、按压恢复；保存并重新打开再运行 | 本例完成过这些点击与保存检查；交付在线可编辑文件及控制位置 |

这条路线中的名称、五个标签和约 420 ms 过渡是案例参数。使用者应替换成自己的图形、状态数量和节奏。先做两个目标之间的点击闭环，再扩展数量；这用于确认当前操作路径，不要求额外建立测试系统。

## 碰壁与处理

| 碰到的现象 | 当时的问题 | 处理方式与实际结果 |
| --- | --- | --- |
| Luau 版本效果可用，但用户难以自行调整状态机 | 绘制和交互集中在代码中，可编辑入口不符合要求 | 移除旧脚本，重建原生图形、时间轴、View Model 和状态机；之后在编辑器中完成五标签点击 |
| 第一次原生版本能切换，但图形和动画弱于脚本版 | 重建时丢了图标曲线、胶囊拉伸及次级反馈 | 重画五个图标，补图标回弹、粒子、按压和分层控制；再查连续切换和释放恢复 |
| 导入返回 `Not allowed`，文件已准备却未进入编辑器 | 当前扩展的导入路径受阻 | 当时未靠同一导入重试解决；后续走编辑器内的制作路径。能替代的只有已获授权的原生制作，不能假称导入成功 |
| 画布或面板位置变化后，旧坐标不再对应原对象 | 操作基于旧视口与旧焦点 | 制作中重新读取画布尺寸、界面状态和当前选中对象后继续；技能不携带那次屏幕坐标 |

**已观察但修复未单独证实：** 记录中出现过 `Possible recursive transitions ... Any -> Any -> Home`。遇到同类警告，应查看实际连线，定位意外的自循环或重复转换，再用点击确认结果。现有记录不足以把这个警告写成“已有确定修复”；不要仅因最终能播放就忽略警告或宣称根因已解决。

## 绑定用户指定的编辑器

沿用用户指定的浏览器和已登录会话。先确认浏览器、标签页 URL、文件和画板，不能根据旧标题或固定坐标直接操作另一个页面。

优先使用可用的专用接口；编辑器画布或属性控件缺少可用 DOM 时，用 Computer Use。每次切换设计/动画模式、缩放画布、滚动面板或更改选中对象后，重新读取界面状态。旧坐标和旧 AX 索引不能跨布局复用。

“已登录”意味着继续现有会话，不应再次要求登录。文件导入被扩展权限阻止时，记录实际拒绝的操作和原因；可用原生绘制完成需求时继续绘制，不反复走同一失败导入路径。

## 将画面分成可编辑对象

先制作一个完整 Tab 的静态状态，再复用其结构：

- 背板与活动指示器或胶囊。
- 独立图标路径、文字和对齐组。
- 根据实际交互范围设置的命中对象。
- 按需要加入独立光点、粒子和装饰。

命名要让用户能找到“图标”“指示器”“选中”“按压”等编辑入口。图标曲线、描边端点、间距和文字基线先达到要求，再接交互。

原生版本要保留脚本原型的视觉细节。不能把原先的自绘图标换成随意符号，删去胶囊拉伸、次级反馈后，仅凭“能切换”宣布完成。

## 分开设计持续状态与瞬时反馈

用一张小表定义本次需要的状态与动作，不预设所有项目都需要四层：

| 职责 | 持续数据或触发 | 控制内容 |
| --- | --- | --- |
| 当前标签 | `selectedTab` 枚举或数值 | 活动位置、配色、标签显示 |
| 主过渡 | 标签变化 | 指示器移动、拉伸、落定 |
| 按压 | 按下与释放 | 图标或按钮缩放与恢复 |
| 悬停 | 进入与离开 | 仅在需求中存在的提示反馈 |

只把彼此独立且确实需要同时工作的反馈分成状态机层。明确各层控制哪些属性，避免两层同时写同一个 Scale 或 Opacity。组件有稳定复用边界时再抽成组件，不因存在多个 Tab 就添加额外体系。

### 新工程与现有 Inputs 工程

2026-09-10 核对的官方文档已将 Inputs 标为旧功能，新工程推荐 **Data Binding / View Model**。本例的 `Navigation.selectedTab` 已跑通这条数据到状态的链路；新任务仍需确认画板实际绑定的实例，不能只创建一个未使用的属性。

**文档核对的另一条分支：** 已有文件使用 Boolean、Trigger、Number Inputs 时，先沿用其实际结构完成本次需求。不要把一次动效修改扩大成全工程迁移；只有本次确有需要或用户要求时才迁移。旧 Inputs 的位置可能在 Animations 面板中，不能照旧教程找固定侧栏。不要将这条维护建议误记为 LUMA 曾完成过 Inputs 到 Data Binding 的迁移。

单选标签宜用一个明确的选择值，而不是多个可能同时为真的选中开关。按压数据与持续选择分开，避免释放时把当前标签清掉。

## 建立真实交互链路

先做一个可见闭环：

`点击命中对象 → Listener 修改选择值 → 过渡条件满足 → 动画与选中画面变化`

Listener 要核对 Target、Listen To、Action 三部分。视觉图标、文字与实际命中区并不天然一致。若对象遮挡命中区或事件穿透，检查层次及 Opaque Target，不在画布外加脚本按钮掩盖问题。

为动画区分基础姿态与过渡轨迹：移动、胶囊伸缩、图标回弹和粒子消散可以有不同落定时刻。静态选中帧不能表现“超出再返回”；弹性需要合适的时间曲线或原生时间轴。

检查过渡条件、混合时长和 Exit Time 对点击响应的影响。用户快速切换时，检查是否被上一段完成条件阻塞，或被重复进入同一状态重置。按当前设计调整，不固定所有过渡为某个时长或模式。

## 证据边界

本案例的成功经验是：保留完整视觉反馈，再把它落实到可编辑对象与原生状态关系。可编辑性不能代替视觉完成度，手动改属性也不能代替真实点击。

本分支不打包旧 `LumaTabBar.luau`：它将绘制与交互放在运行时代码中，与用户要求的原生图形和可视状态机不符。浏览器操作也不保存成固定坐标脚本；按当前工具接口和实际界面继续操作。需要检查导出的演示视频时，使用 [参考视频分支](reference-video.md) 的抽帧脚本。

上述成功标志来自当时制作和重新打开后的检查，不证明旧在线文件今天仍是同样状态。本次也未对任意新文件重新实跑；使用者按自己的文件读取当前状态。

## 完成检查与交付

- 在播放或状态机预览中实际点击每个目标，不能只手动改选择值。
- 检查顺序切换、跨标签切换、连续切换，以及已有按压反馈的释放恢复。悬停不在任务中时不用额外添加。
- 回到编辑模式，确认图形、状态、过渡、监听器和数据入口可定位、可修改。
- 确认保存，再刷新或重新打开检查一次本次修改。交付在线编辑文件；需要运行接入时，再导出 `.riv` 并记录画板、状态机与数据属性名称。
- 运行资源、屏幕录像和脚本原型不能替代可编辑在线文件。

用户明确要求绘制图形和状态机时，不交付 Luau/Canvas 自绘实现。以后若用户明确选择 Rive 脚本能力，按该次授权制作，不把本案例偏好当作软件永远禁止脚本。
